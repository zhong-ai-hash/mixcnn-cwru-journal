## 1. 协议与完成度

- 数据：CWRU 原始 `.mat` 重建，2000 窗 × 1024 点；40 条记录；10 类 × 200 窗；4 个负载 × 500 窗。
- 负载来源：38/40 条由 RPM 推断；`X098`、`X099` 两条 normal 记录无 RPM 字段，按文件号回退。
- 切分：4 折 leave-one-load-out（LOBO）+ 1 个随机窗口切分对照。
  - LOBO 每折：train 1350 / val 150 / test 500，test 负载单一。
  - random 折：train 1400 / val 200 / test 400，test 覆盖 0–3 hp。
- 训练：20 epoch，batch 32，lr 1e-4；5 个种子（0–4）；2 个变体（base、noPad）；2 种训练条件（clean、noise）。
- 规模：5 折 × 2 变体 × 2 条件 × 5 种子 = 100 run。
- 完成度：JSON 100/100，权重 100/100，预测 100/100；全部 `complete=true`。
- BN 采样：三套 BN 库统一 `seed_base=40000`，可在同一噪声抽样下做窗口级配对。

解释时需注明：random 折与 LOBO 折的测试集大小和负载构成不同，`gap` 是“实际常用随机切分相对 LOBO 的乐观偏差”，不是严格同分布配对。base/clean 在 0 dB 的负 gap 不能解读为“泄漏有害”，它主要反映 random 测试集覆盖全部负载、题目构成不同。

## 4. 架构效应（noPad - base，按种子配对）

| 训练条件 | metric | LOBO 差值 | 随机切分差值 |
|---|---|---:|---:|
| clean | clean acc | +1.28 ± 1.81（t=1.58） | +0.15 ± 0.22 |
| clean | 0 dB acc | +29.64 ± 8.34（t=7.95） | +40.85 ± 12.59 |
| noise | clean acc | -0.20 ± 0.92（t=-0.48） | -0.10 ± 0.14 |
| noise | 0 dB acc | -0.31 ± 0.57（t=-1.24） | -0.01 ± 0.18 |

结论：clean 训练下，NoPad 的干净精度与 base 无显著差异，但 0 dB 鲁棒性大幅提高；一旦训练时加入噪声，两者的干净精度和 0 dB 精度都等价。架构差异不是普通意义上的“谁更准”，而是“谁在训练/测试噪声失配时更稳”。

## 5. BN 库在 0 dB 测试集上的表现

| group | as-trained | BN clean | BN 0 dB | BN 4 dB |
|---|---:|---:|---:|---:|
| base / clean | 37.73 | — | 86.21 | 63.30 |
| base / noise | 97.53 | 87.93 | 97.31 | 97.14 |
| noPad / clean | 67.37 | — | 95.64 | 86.42 |
| noPad / noise | 97.21 | 88.73 | 96.81 | 96.42 |

结论：BN 重校准对 clean 训练模型是大幅补救（base +48.5 点，noPad +28.3 点），但对已经用噪声训练的模型没有增益，甚至略降。BN 不是独立于训练的“第二个杠杆”，而是失配条件下的补偿机制。

## 6. 对期刊版的直接含义

1. 会议版的随机窗口切分确实乐观：clean 精度高估约 3.1–4.2 点；0 dB 下 clean 训练的 noPad 高估约 8.7 点。
2. 加噪训练基本消除了切分泄漏差（clean 1.35–1.45 点，0 dB 1.60–1.91 点），说明噪声增广不仅提升鲁棒性，也降低了对窗口级泄漏的依赖。
3. 架构排序依赖训练条件：clean 训练下 NoPad 的 0 dB 优势约 29.6 点（LOBO，t=7.95）；加噪训练后差异消失。这比会议版“架构不可排序”的结论更精确。
4. BN 双库的价值集中在 clean 训练 + 噪声测试的失配场景；部署时应先判断噪声档位，再决定是否切换 BN，而不是无条件保留双库。
5. M1b 尺寸外推可以做，但优先级低于：外部基线、可部署噪声档位检测器、JNU 跨数据集复现。
