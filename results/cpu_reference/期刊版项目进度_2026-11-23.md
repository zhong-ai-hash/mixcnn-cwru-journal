## 0. 一句话状态

M1 的 100 个 run 已完成。M1c 之后，期刊版主线需要从会议版的
“架构不可排序、BN 是第二杠杆”再向前一步，但**不能**写成
“噪声训练消除了泄漏”：

> 噪声训练主要抬高的是“无泄漏基线”，而不是消除同录音泄漏。泄漏臂的
> clean 准确率在 clean 训练和 noise 训练下都停在 98.5–99.0，说明窗口级
> 随机切分给出的是一个由记录内插值决定的、可复现的上界；噪声训练把无泄漏
> 基线从 92.0/93.1 抬到 97.4/97.1，于是“表观泄漏差”从 6.6/5.8 缩到
> 1.0/1.5。随机−LOBO 的差必须拆成跨负载泛化差与记录内泄漏两部分，不能
> 整体称为泄漏。

架构与 BN 的结论不变，但同样要限定测量范围：

> 架构与 BN 的可见效应只在训练/测试噪声失配时才出现；一旦噪声训练把
> 准确率推到 97% 以上，剩余提升空间不足 3 点，BN 的“无增益”部分是
> 天花板约束，不能反推为 BN 在噪声训练下必然无用。

**数据集边界（JNU 之后补）：** 上述“噪声训练是主效应”只在 CWRU 上成立。
JNU 跨转速（600/800→1000 rpm）复现了方向但没有复现幅度：0 dB 仅
+5.5/+7.8 点（p=0.38/0.26），跨转速本身把 clean 精度压到 ~82%。
因此主效应必须写成“CWRU 上的主效应”，JNU 的作用是给出外部效度边界，
而不是把结论推广成跨数据集规律。

这一定位比会议版更适合 Measurement：论文测的是“99% 依赖哪些实验条件”，而不是宣称某个轻量网络失效。

**外部基线后的边界修正：** 即便只谈“缩小表观协议差”，该现象目前也只成立
在 MIXCNN 变体族内。WDCNN 与 ResNet-1D 在同一 20-epoch 协议下仍保留
2.8–5.0 点的 random−LOBO 差，所以论文不能把它写成所有架构的普适规律。

## 0.1 可主张的边界（写作用）

**A. 可直接主张（描述性，限定在 CWRU 10 类 / 40 条录音 / 本协议）**

- 窗口级随机切分相对 LOBO 高估 clean 精度约 3–4.5 点（MIXCNN 两个变体
  与 WDCNN/ResNet-1D 均同向；精确值以 `curve/summary.json` 为准）。
- 同录音泄漏单独可造成 5.84–6.56 点虚高（clean 训练）；四个“泄漏”格的
  clean 精度都落在 98.5–99.0。
- 噪声训练把无泄漏 clean 基线抬高 4–5 点、0 dB 从 31.8/58.8 抬到
  97.6/96.7。
- BN 重校准在 clean 训练 + 0 dB 下把 base 从 31.8 拉到 86.2、NoPad 从
  58.8 拉到 95.5；噪声训练模型的残余增益不足 3 点。

**B. 有条件主张（必须带限定词）**

- “噪声训练吸收协议差/架构差/BN 差”只在 MIXCNN 变体族、本数据集、
  20 epoch 固定预算内成立，且部分是天花板效应。
- 架构排序只在训练/测试噪声失配时可见；匹配噪声条件下差异 ≤1 点，
  落在测量分辨率内。
- 随机−LOBO 差 = 跨负载泛化差（主体）+ 记录内泄漏（1–2 点）；
  不能整体归因于泄漏。

**C. 不可主张**

- 不能做 SOTA 对比：基线未逐模型调参，epoch 预算固定。
- 不能外推为“所有架构的普适规律”。
- 不能说“99% 是假的”：应说“99% 依赖一组可测量的实验条件”。
- 不能宣称已解决录音级泛化：M1c 只隔离了同录音泄漏，跨录音、跨工况
  仍是 LOBO 框架内的有限证据。
- 不能宣称可部署：INT8/延迟/内存尚未测量，双 BN 仍是 oracle 上界。

`aligned_summary.json`**。

对齐后的 0 dB LOBO 均值（`eval_seed=50000`）：

| group | clean acc (at) | at | BN clean | BN 0 dB | BN 4 dB |
|---|---:|---:|---:|---:|---:|
| base / clean-trained | 96.05 | 31.82 | 31.06 | 86.22 | 63.46 |
| base / noise-trained | 98.26 | 97.58 | 87.96 | 97.31 | 97.09 |

### 2.2 泄漏与跨负载拆分：`m1c_leak.py`

设计：

- 固定测试集：load0 每条录音的后 25 窗，共 250 窗。
- Arm A `no_overlap`：load1–3 全部 1500 窗训练，训练中不含任何测试录音。
- Arm B `recording_leak`：从 Arm A 去掉 load3 每条录音的前 25 窗，换成
  load0 每条录音的前 25 窗；训练仍为 1500 窗，测试集与 Arm A 完全相同。
- 差值 `Arm B − Arm A` 即同录音早期窗进入训练后的净效应；替换按类别和
  录音内位置匹配，尽量减少负载构成变化。

dry-run 已通过：

```text
no_overlap      train=1500 test=250 train_loads=[1, 2, 3] test_loads=[0] recording_overlap=0 leak_windows=0
recording_leak  train=1500 test=250 train_loads=[0, 1, 2, 3] test_loads=[0] recording_overlap=10 leak_windows=250
runs queued: 40
```

两臂的逐类窗口数均为训练 150/类、测试 25/类；泄漏臂与测试集重叠的录音为
`97, 105, 118, 130, 169, 185, 197, 209, 222, 234`，共 10 条。

输出目录：`results/journal/m1c/`。  
状态：**已完成 40/40 run（JSON 40、预测 NPZ 40），汇总见 `m1c/summary.json`**。

结果（5 种子配对，效应 = `recording_leak − no_overlap`，正值为泄漏带来的
虚高）：

| 训练条件 | 变体 | clean：无泄漏 → 泄漏 | 效应（95% CI） | p |
|---|---|---:|---:|---:|
| clean | base | 92.00 → 98.56 | +6.56 (+0.62, +12.50) | 0.037 |
| clean | NoPad | 93.12 → 98.96 | +5.84 (+0.77, +10.91) | 0.033 |
| noise | base | 97.44 → 98.48 | +1.04 (−0.26, +2.34) | 0.090 |
| noise | NoPad | 97.12 → 98.64 | +1.52 (+0.98, +2.06) | 0.0015 |

0 dB 测试（效应 = `recording_leak − no_overlap`）：

| 训练条件 | 变体 | 0 dB：无泄漏 → 泄漏 | 效应（95% CI） | p | 可解释性 |
|---|---|---:|---:|---:|---|
| clean | base | 32.46 → 32.47 | +0.02 (−4.95, +4.99) | 0.993 | 两端均在地板，不可解释 |
| clean | NoPad | 55.98 → 61.38 | +5.40 (−3.44, +14.24) | 0.165 | 方差大，未检出 |
| noise | base | 95.11 → 97.18 | +2.07 (+0.61, +3.54) | 0.017 | 可检出 |
| noise | NoPad | 95.27 → 97.46 | +2.19 (+1.01, +3.37) | 0.0068 | 可检出 |

三条读法，必须按这个顺序写进论文：

1. **泄漏臂是一个稳定的天花板。** 四个“泄漏”格的 clean 准确率分别是
   98.56 / 98.48 / 98.96 / 98.64，跨训练条件和 padding 变体只差 0.5 点。
   这不是“噪声训练吸收了泄漏”，而是记录内插值本身就能把同一测试集推到
   98.5–99.0。
2. **变的是无泄漏基线。** clean→noise 训练把无泄漏臂抬了 5.4 点（base）和
   4.0 点（NoPad），所以表观差值缩小。把“差值缩小”归因于泄漏消失，是
   把天花板效应误读成机制。
3. **泄漏效应在噪声训练后仍可检出。** NoPad 在 clean 下 +1.52（p=0.0015）、
   0 dB 下 +2.19（p=0.0068）；base 在 0 dB 下 +2.07（p=0.017）。方向一致，
   量级 1–2 点。这足以支持“随机切分偏乐观”，但不足以支持“偏乐观 6 点”——
   后者只在 clean 训练的干净测试上成立。

因此正文的协议段应写成“random−LOBO 的差包含跨负载泛化差与记录内泄漏，
M1c 把后者单独估计为 1–2 点（噪声训练）”，而不是把 3–4 点全部叫泄漏。
同理，clean-trained + 0 dB 的格子处于地板，不能用来检验泄漏效应；这是
测量量程限制，不是零效应。

**一个必须写进图注的限制：** M1c 的绝对精度不能与 M1 的 LOBO 直接比较。
M1 的测试集是留出负载内随机分层 20%（500 窗，覆盖录音全程），M1c 固定取
每条录音最后 25 窗（250 窗，集中在录音后段）。两者的测试子集不同，M1c 的
92.0/93.1 低于 M1 的 96.05/95.52，可能同时包含“后段更难”和“测试集更小”
两个因素。M1c 只用于两臂相减，不用于跨实验比较绝对水平。

## 4. JNU 外部验证

数据：`data/journal/jnu_windows.npz`，600 窗，4 类（N/IB/OB/TB），
600/800/1000 rpm，每文件 50 窗，窗口 4096 点（50 kHz，81.9 ms）。

脚本：`code/journal/protocol_jnu.py`。

默认主验证：

- 训练：600 + 800 rpm
- 测试：1000 rpm
- train/val/test = 360/40/200
- Ref/NoPad × clean/noise × 3 种子 = **12 run**

dry-run 已通过，脚本也支持用 `--folds 600 800 1000` 做三折留一转速稳健性检查
（36 run）。输出目录：`results/journal/jnu/`。  
状态：**已完成 12/12 run，汇总见 `jnu/summary.json`**。

结果（3 种子均值 ± SD，单位 %）：

| 训练 / 变体 | clean | −4 dB | 0 dB | 4 dB | 8 dB | 12 dB |
|---|---:|---:|---:|---:|---:|---:|
| clean / base | 82.00±3.9 | 30.8±8.6 | 35.3±9.5 | 47.2±5.4 | 67.7±5.7 | 76.5±4.4 |
| noise / base | 77.8±3.6 | 28.5±0.5 | 40.8±1.1 | 55.8±3.4 | 70.3±5.5 | 74.9±3.9 |
| clean / NoPad | 81.8±3.7 | 34.5±15.8 | 35.3±12.1 | 48.7±9.1 | 64.0±11.2 | 73.6±7.4 |
| noise / NoPad | 78.7±4.7 | 31.3±4.4 | 43.0±3.4 | 57.8±6.0 | 68.7±7.1 | 73.6±5.2 |

配对检验（noise − clean，3 种子）：

| 变体 | 0 dB | 4 dB | 8 dB | clean |
|---|---:|---:|---:|---:|
| base | +5.50 (p=0.38) | +8.53 (p=0.16) | +2.52 (p=0.73) | −4.17 (p=0.40) |
| NoPad | +7.77 (p=0.26) | +9.10 (p=0.33) | +4.67 (p=0.70) | −3.17 (p=0.57) |

三条读法：

1. **跨转速本身是主导因素。** clean 精度只有 ~82%，远低于 CWRU 同条件的
   96% 以上；0 dB 下两组都接近 4 类随机水平（25%），说明转速移位 + 白噪声
   共同摧毁了判别信息。
2. **噪声训练方向一致，但没有复现 CWRU 的幅度。** CWRU 上 0 dB 从
   ~32/67 拉到 ~97；JNU 上只从 35.3 拉到 40.8/43.0（+5.5/+7.8），
   3 种子下不显著。4 dB 的 +8.5/+9.1 是最大的方向性增益，但 p=0.16/0.33。
3. **变体差异不存在。** noPad−base 在任一条件下都不超过 3.7 点，
   全部 p>0.24；JNU 不支持“padding 变体在某条件下更好”。

因此 JNU 的定位是**外部效度边界**，不是第二个主结果：它说明 CWRU 上
“噪声训练是主效应”不能自动外推为跨数据集规律，效应大小取决于移位类型
（噪声 vs 转速）与故障信息是否还在噪声下存活。

限制（必须写进正文）：

- 只有 3 个种子，配对差 SD 达 6.7–18.3 点，0–4 dB 的增益未建立显著。
- 4096 点窗口、360 个训练窗；全局逐位置 `StandardScaler` 用 360 个样本
  估计 4096 个位置的均值/方差，属数据受限，且跨转速相位未对齐。
- 4096 点是为了与 CWRU 的 85 ms 物理时长对齐，但卷积核覆盖的物理时间
  比 CWRU 短 4 倍，感受野不严格一致。

实测成本：4096 点输入下，模型主体在 1024 长度上运行（CWRU 为 256），
单 run 训练约 39 分钟、评估（5 档 SNR × 10 次抽样 × 200 窗）约 37 分钟，
合计约 75 分钟；6 进程两波，墙钟约 2.5 小时。机器共 18 个逻辑核，但同时
只有 8 GB 可用内存，12 进程会逼近 OOM，因此保持 6 进程。
