# 当前工作说明与 TIM/TII 投稿路线

日期：2026-11-20  
依据：`results_v2/` 的 60 次训练、`paper/main_A_v2.tex` 的四页新稿，以及旧版 `results_seed3.json`。

## 一、当前工作实现了什么

这项工作不是在原 MIXCNN 上再刷一个准确率点，而是把“99% 到底说明了什么”拆成可复核的实验问题。

已实现的内容：

1. 在随包 CWRU 数组（1010 × 1024，10 类各 101 条）上复现 MIXCNN 的 PyTorch 版本，参数量 81,674。
2. 定位并修正原训练脚本的实质问题：训练循环内调用 `test()`，`model.eval()` 后不恢复 `train()`，导致第一个 step 之后 BN 统计量冻结、训练进入 inference mode。
3. 建立六个局部变体：Ref、NoRes、NoPad、Soft、MS(pad)、MS(no-pad)，并把“多尺度”和“去填充”拆成两个干预。
4. 建立 protocol v2：
   - 固定外层切分 70/10/20，707/101/202；
   - scaler 只在训练集 fit；
   - 5 个初始化种子共享同一测试集；
   - 每个窗口独立抽 SNR 的 AWGN；
   - 训练 SNR ~ U[−4,10] dB；
   - 测试 SNR 为 −4/0/4/8/12 dB，每点 10 次抽样；
   - clean/noise 权重 × clean/4 dB/0 dB BN 统计量的交叉控制；
   - 保存每个 run 的 JSON、预测正确性 NPZ、汇总、表格和图。
5. 完成 60 次主训练（6 变体 × 2 分布 × 5 种子），并自动生成 Table II、Table III、噪声曲线和配对置信区间。
6. 新增简单基线：128-bin log-FFT + logistic regression，在同一固定切分上 clean 100%；noise-trained 版本 0 dB 81.7%。
7. 写成新的四页稿：`paper/main_A_v2.tex` / `main_A_v2.pdf`。旧 `main_A.tex` 保留作 v1 对照。

## 二、相对原来的工作增加了什么

原来的核心是“3 个变体 × 2 种训练分布 × 3 个种子 + BN 重校准”。v2 增加了四类东西：

| 原来 | 现在 | 作用 |
|---|---|---|
| 随机窗口切分，scaler 在全部数据上 fit | 固定外层切分，train-only scaler | 去掉预处理泄漏，保证配对比较 |
| 3 个变体 | 6 个变体，多尺度/去填充拆开 | 避免把两个干预混为一个结论 |
| 3 个种子，切分和初始化同时变化 | 5 个种子，固定切分 | 把差异归因于初始化/训练，而不是切分变化 |
| 每 batch 一个 SNR，batch RMS 定功率 | 每窗口一个 SNR，逐窗口 RMS | 让训练噪声与论文声明的 SNR 一致 |
| 只报 0/4 dB | 5 档 SNR × 10 draws | 画出完整噪声曲线 |
| 只比较 clean/noise 训练后的 BN | 2×2 权重 × BN 统计量交叉 | 分离权重分布与归一化统计量 |
| 只报均值和总体标准差 | 样本 SD + 5 种子配对 95% CI | 让“差 0.2 点”是否可解释变得明确 |
| 只有 CNN 变体 | FFT+logreg 强饱和基线 | 证明 clean 99% 不是架构独有 |

## 三、发现了什么

### 3.1 干净集已经饱和

- 128-bin log-FFT + logistic：clean **100%**。
- 六个 CNN 变体：clean **97.0–98.5%**。
- NoPad − Ref：**+0.10 点**，95% CI **[−0.70, +0.90]**。
- 202 个测试窗口中，1 个窗口 = **0.50 点**。

结论不是“所有架构永远无效”，而是：在这个窗口级 CWRU 切分上，clean accuracy 已经没有分辨率去排序这些局部变体。

### 3.2 逐窗口噪声训练是大效应

| 模型 | clean-trained 0 dB | noise-trained 0 dB | 增益 |
|---|---:|---:|---:|
| Ref | 43.47 | 97.38 | +53.91（CI 47.59–60.24） |
| NoPad | 59.65 | 97.70 | +38.05（CI 32.88–43.22） |

对应的 clean 变化：

- Ref：−3.47 点，CI [−8.61, +1.68]；
- NoPad：−1.29 点，CI [−3.06, +0.48]。

因此，在修正后的逐窗口协议下，没有检测到明显的“为了抗噪牺牲干净集”的代价。旧稿里 NoPad 的 72.7 → 87.4 权衡没有复现。

### 3.3 NoPad 是真实的成本-鲁棒性 Pareto 改进

- clean：NoPad 98.51 vs Ref 98.41；
- 4 dB：95.76 vs 89.10；
- 0 dB：59.65 vs 43.47（+16.18，CI 9.63–22.73）；
- 参数量同为 81,674；
- 前向 FLOPs：38.8M vs 153.0M，约减少 75%。

这不是说“padding 一律有害”，而是说：在这个实现里，后面三个 block 的大部分计算花在没有信号的位置上。删掉它，clean 不掉，clean-trained 的低 SNR 反而更好。

### 3.4 多尺度和软阈值没有承担贡献

- 纯多尺度（保留 padding）：clean 98.02，0 dB 41.84；相对 Ref 的差值为 −0.39（CI −0.91–0.12）和 −1.63（CI −9.54–6.28）。
- 多尺度 + 去填充：clean 97.32，0 dB 56.12。
- Soft：clean/4/0 为 98.41/88.96/43.52，与 Ref 基本重合。
- NoRes：clean −1.39 点（CI −5.26–2.48），0 dB +3.21 点（CI −0.86–7.28）。

原来的“18 点多尺度惩罚”是把多尺度和去填充混在一起造成的，不是纯多尺度效应。

### 3.5 BN 统计量真实，但不是旧稿说的“唯一旋钮”

以 NoPad 为例：

| 权重训练 | BN 统计量 | Clean | 4 dB | 0 dB |
|---|---|---:|---:|---:|
| clean | clean | 98.51 | 95.76 | 59.65 |
| clean | 0 dB | 72.87 | 91.80 | 97.65 |
| noise | clean | 98.32 | 97.63 | 94.95 |
| noise | training | 97.23 | 97.46 | 97.70 |

解释：

- clean-trained 权重 + 0 dB 统计量：0 dB 从 59.65 升到 97.65，但 clean 掉到 72.87；
- noise-trained 权重 + clean 统计量：clean 仍为 98.32，0 dB 仍有 94.95；
- 双 BN 库：clean 用 clean 统计量、0 dB 用 noise 统计量，可达 98.32/97.70。

所以“单一固定 BN 库不能同时最优”成立；“模型不能两者兼得”不成立，双库可以。

## 四、证实了什么、否证了什么

| 命题 | 当前判定 |
|---|---|
| 原训练脚本的 eval-mode 缺陷是实质问题 | **证实** |
| CWRU clean 99% 已经被简单频谱基线饱和 | **证实** |
| 逐窗口噪声训练能大幅提高 0 dB 准确率 | **证实** |
| NoPad 明显降低 FLOPs，clean 不掉 | **证实** |
| “干净准确率与架构完全无关” | **过度表述**；应改为“低于当前测试分辨率” |
| “噪声准确率由训练分布单独决定” | **否证**；BN 统计量和噪声粒度同样关键 |
| “多尺度在 0 dB 低 18 点” | **否证**；旧比较混淆了去填充 |
| “一个模型不能同时在 clean 和 0 dB 都好” | **否证**；双 BN 库可以 |
| “BN 重校准是单向旋钮” | **弱化**；逐窗口噪声下噪声训练本身已接近两端，BN 是第二杠杆 |

## 五、如果投 TIM 或 TII，还需要补什么

当前 v2 是一篇诚实的“基准审计 + 受控再评估”，不是 TII/TIM 级别的完整方法论文。要投这两个期刊，至少需要以下模块。

### 5.1 跨记录/跨工况切分（最高优先）

现在只有打包的 `cwru_data.npy`，没有 recording ID。需要从 raw CWRU 重建窗口，记录 load、fault size、file/recording ID，并做：

- recording-level split；
- 或 load/fault-size 跨组切分；
- 报告与 window-level 结果的差值。

**关系**：v2 证明“窗口级 clean 结果饱和”；这一步回答“结论是否 survive 非泄漏切分”。

**贡献**：把论文从“同一个 recording 内部的插值”提升为“跨记录泛化”。

### 5.2 外部基线

在同一 v2 协议下加入：

- WDCNN；
- DRSN；
- 1D-CNN / ResNet-1D；
- 已保留的 FFT+logreg。

**关系**：当前只比较 MIXCNN 内部局部变体；外部基线决定 NoPad/BN 结论能否与文献对话。

**贡献**：说明“不是我们没调好一个模型”，而是基准/协议层面的现象。

### 5.3 跨域实验

建议 CWRU → SEU 齿轮箱，或 SEU 20 Hz → 30 Hz：

- clean 训练 → 目标域测试；
- noise 训练 → 目标域测试；
- dual-BN / target-BN 的迁移；
- 目标域无标签校准。

**关系**：v2 的 BN 结论目前只在同分布不同 SNR 上成立；跨域才检验它是否具有工业意义。

**贡献**：从“同数据集噪声鲁棒”提升为“跨部件/跨工况可迁移”。

### 5.4 把 oracle 双 BN 变成可部署方法

当前双 BN 是“已知 SNR 后选库”的上界，不是完整方法。需要：

- 训练一个噪声水平/分布检测器；
- 按检测结果切换 BN 库；
- 报告误切换代价、延迟、内存；
- 与单一 BN、AdaBN、测试时自适应比较。

**关系**：这是把 v2 的机制发现转化为 TII 可审的方法贡献。

**贡献**：一个轻量的“噪声感知 BN 切换”部署策略，而不是又一个大网络。

### 5.5 测量与部署指标

如果投 TIM，建议补：

- 训练/推理墙钟、FLOPs、参数量；
- INT8/ONNX 或 MCU 上的 flash/RAM/延迟；
- 不同线程/硬件的重复计时；
- 校准指标（ECE/NLL）与误报率。

**关系**：NoPad 的 75% FLOPs 下降已经在 v2 中成立；TIM 需要把它变成测量学意义上的部署证据。

### 5.6 统计与可复现性

- 5 个 split × 5 个初始化，或至少 5 个 split；
- 预注册 ±0.5 点等价边界；
- 配对 bootstrap / McNemar；
- 完整 JSON、预测、环境锁、数据校验和；
- batch-level vs per-window 噪声的受控消融（解释旧结论为何反转）。

## 六、与现有工作的关系

可以把工作分成两层：

1. **v2（现在）**：发现和归因。回答“clean 99% 是什么、噪声训练为何有效、BN 统计量起什么作用、NoPad 是否值得”。
2. **期刊版（下一步）**：外部有效性和部署。回答“换 recording/工况/硬件后是否仍成立，能否变成可部署策略”。

两者不是两个故事，而是同一研究链：

- v2 提供机制和协议；
- 期刊版提供泛化、基线、跨域和部署；
- 如果期刊版去掉 v2，就只是又一个模型对比；如果只有 v2，则更像 workshop/负结果论文。

## 七、科学问题、贡献与投稿意义

### 科学问题

> 在轴承故障诊断的饱和基准上，clean accuracy、噪声鲁棒性和部署成本分别由架构、训练分布还是归一化统计量决定？在非泄漏、多种子、逐窗口噪声协议下，哪些结论仍然成立？

### 主要贡献

1. 证明 clean CWRU 的 99% 不能作为架构证据：简单频谱基线 100%，六个 CNN 变体差异小于一个测试窗口。
2. 证明逐窗口噪声训练是大幅、可重复的干预：0 dB 提升 38–54 点，clean 损失未检测到。
3. 证明 NoPad 是成本-鲁棒性 Pareto 改进：同等参数、同等 clean、0 dB 更好、FLOPs 约 1/4。
4. 证明 BN 统计量是第二杠杆，并给出双 BN 库的上界；把旧稿的“不能两者兼得”修正为“单一固定库不能，双库可以”。
5. 给出一个可复现的评估协议，并展示 batch-level 噪声会把结论带向另一个方向。

### 对 TIM/TII 的意义

- **TIM** 更匹配“测量协议、评估有效性、成本/延迟、可复现性”。当前 v2 已经接近 TIM 的短文/会议版；补嵌入式和跨记录后可投 TIM。
- **TII** 更看重“工业部署、跨域、方法完整性”。当前 v2 的方法贡献还偏弱，必须补 dual-BN 检测器、外部基线和 SEU 跨域，才像 TII 正刊。
- 如果只把当前 v2 直接投 TII，审稿人最可能说：只有一个数据集、没有外部基线、没有跨域、双 BN 只是 oracle、没有真实部署。这个风险必须在投稿前解决。

## 八、建议的执行顺序

| 阶段 | 内容 | 目标 |
|---|---|---|
| 现在 | 用 `main_A_v2.tex` 投 4 页会议/workshop 或预印本 | 先锁定“饱和基准 + 协议 + BN”发现 |
| 1 周 | raw CWRU recording split + WDCNN/DRSN | 建立非泄漏外部比较 |
| 1–2 周 | SEU 跨域 + dual-BN 检测器 | 形成 TII 方法闭环 |
| 1 周 | 嵌入式/INT8/延迟 | 形成 TIM 测量闭环 |
| 3–5 天 | 统计、图、复现包 | 投稿质量门 |

**推荐**：先把 v2 作为 4 页短文定稿；不要现在直接投 TII 正刊。若目标是 TIM，优先补 recording split、外部基线和部署测量；若目标是 TII，优先补跨域和可部署 dual-BN 方法。
