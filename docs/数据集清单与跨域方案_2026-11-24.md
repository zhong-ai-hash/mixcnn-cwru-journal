## 2. Paderborn 转换方案

结构：每个轴承 4 个工况 × 20 条记录，每条 4 s @ 64 kHz（256k 点）。

```
K001\K001\N09_M07_F10_K001_1.mat
  X[0] = vibration_1 (64 kHz)
  Y[]  = 标签字段（K001 / N09 / M07 / F10 / 损伤码）
```

主工况选 `N09_M07_F10`（900 rpm，0.7 Nm），与 CWRU 的负载变化形成互补。

类别：

| 前缀 | 类别 | 轴承数（官方） |
|---|---|---:|
| K00x | healthy | 6 |
| KAxx | outer ring | 12 |
| KIxx | inner ring | 11 |
| KBxx | ball | 3 |

主实验用 3 类（healthy / outer / inner），4 类作为补充（ball 只有 3 个轴承，
单独报告）。

窗口：4096 点（64 ms），stride 4096；每条记录 62 窗。为控制规模，每条记录
均匀取 16 窗 → 每轴承 320 窗，约 29 个轴承 → 约 9k 窗。

切分：

- `paderborn_lobo_bearing`：留一轴承（unseen bearing），主指标。
- `paderborn_group`：按记录（measurement 文件）随机 70/15/15，10 个切分种子。

## 3. SEU 齿轮箱

`seu_gear_signal_TD.mat`：`AccTimeDomain` 3600×936，按列分成 3 类 × 1200 样本：
normal / light pitting / heavy pitting（与 `D:\SEU_gear_db\step1_split_data.py`
的类别顺序一致）。

窗口已是 936 点，不再切分。没有 recording ID，只能做样本级分层切分；
因此它**不能**用来支持“录音级泄漏”结论，只作为跨部件 sanity check。

## 4. XJTU-SY

留作后续工作，避免审稿人质疑任务不一致。
