审查日期：2026-11-20  
审查范围：`README.md`、`paper/main_A.tex`、全部结果 JSON、主实验代码、过程文档；未把 B 线（Sallen-Key/TinySSM）当作主论文证据。

## 一、结论先行

**不建议推倒重来，但当前稿不能按现有标题和结论投稿。**

项目的数据、代码、18 次主实验和 BN 对照是真材料，核心现象也值得写；问题在于论证把三个不同因素混在了一起：

1. 架构改动；
2. 训练分布；
3. BatchNorm 统计量；
4. 数据切分与标准化协议。

当前稿把第 2 个因素说成主要原因，但实验没有把第 3 个因素单独控制住。更准确、也更有新意的中心论点应是：

> 在已经饱和的 CWRU 窗口级基准上，干净准确率不能区分架构；噪声训练带来的大幅提升，很大程度上由 BN 统计量与测试分布的匹配程度介导。单一 BN 配置只能在干净端和噪声端之间取舍，但双 BN 统计量库可以在两端切换。

建议先按“可复现的负结果/基准审计”写成 4 页会议短文；若目标是 IEEE TII/TIM 类期刊，再补 recording-level 切分、外部基线和跨域实验。预计短文 1 周，期刊版 4–6 周。

## 二、已经核实为真的部分

### 2.1 结果文件与主表数字

- `results_seed3.json` 有完整的 18 行：3 变体 × 2 分布 × 3 种子。
- 表 II、表 III 的均值与 JSON 逐项吻合，保留两位小数后没有发现算错。
- 表 II/III 的标准差对应**总体标准差**（`ddof=0`）。若按 3 个种子的样本标准差，误差棒会更大。例如 Ref clean 的 0.27 会变成约 0.33。
- 训练时间 423/60/113 s 是对 Ref/NoPad/MS 各 6 次训练（3 种子 × 2 分布）取的均值，不是“每变体 3 次”。

### 2.2 原训练脚本的实质缺陷

`model_2_view.py` 在训练循环内调用 `test()`，而 `test()` 设置 `model.eval()` 后不恢复 `train()`。因此第一个 step 之后 BN 统计量冻结，后续训练实际处于 inference mode。这是实质性的训练缺陷，足以解释“照原脚本跑不出原论文训练过程”。

### 2.3 成本结果

用 `torch.utils.flop_counter` 对单样本前向计数：

| 变体 | 参数量 | 前向 FLOPs |
|---|---:|---:|
| Ref | 81,674 | 153.0 M |
| NoPad | 81,674 | 38.8 M |
| MS（当前含去填充） | 84,746 | 40.3 M |

NoPad 的前向 FLOPs 约为 Ref 的 1/3.95（减少约 75%），训练墙钟约快 7 倍。这个结果支持“去掉零填充显著降本”，但“四分之五算力”更准确的说法是“约四分之三的前向计算”。

### 2.4 干净基准确实饱和

在同一随机切分上做一个审计用基线：对原始波形取 128 个 log-FFT 幅度 bin，接 `StandardScaler + LogisticRegression`，测试准确率为 **100%**；64 个 bin 时为 99.01%。这不是论文结果，但说明干净集的 99% 主要反映任务可分性，而不是某个 CNN 架构的独特能力。

## 三、阻断性问题（P0）

### P0-1：当前 `MS` 不是“纯多尺度”，同时去掉了零填充

`code/variants.py:103` 中：

```python
multi=dict(multi=True, pad=False)
```

因此表 II 的 `MS` 相对 Ref 同时改变了：

- 单核 k=64 → 双分支 k=8/k=64；
- 保留 1024 长度 → 去掉 padding，长度变为 249。

论文却把它写成“adds a genuine multi-scale pair”，并把 0 dB 的 18 点下降归因于多尺度。这个归因不成立。

我已新增 `multi_pad`（保留 padding，只改多尺度）和 `run_pure_ms.py`。沿用当前有缺陷协议的 3 种子诊断结果：

| 变体 | 训练 | 干净 Acc | 4 dB | 0 dB |
|---|---|---:|---:|---:|
| 当前 MS（多尺度 + 去填充） | clean | 99.45 | 48.98 | 19.45 |
| 纯多尺度 `multi_pad` | clean | 96.92 | 50.06 | 27.09 |
| 当前 MS（多尺度 + 去填充） | noise | 54.12 | 90.98 | 75.07 |
| 纯多尺度 `multi_pad` | noise | 86.47 | 88.94 | 76.02 |

去除 padding 把“多尺度”的干净准确率从 96.9 推到 99.45，同时把噪声训练的干净准确率从 86.5 压到 54.1。两者不是同一个干预，不能合并解释。

**修复：** 要么把当前行改名为 `MS−Pad`，要么主表使用 `multi_pad` 作为 MS；两者都保留时，必须明确是 2×2 设计（多尺度有/无 × padding 有/无）。

### P0-2：训练分布与 BN 统计量混淆，且“cannot be both”过强

当前设计只比较：

- clean-trained + clean BN；
- noise-trained + noise BN。

这同时改变了权重和 BN 统计量。论文再用 clean 数据重估 noise-trained 模型的 BN，得到表 III，但没有做反向控制：clean-trained 模型在噪声统计量下会怎样。

我做了 NoPad 的 3 种子诊断控制（沿用当前有缺陷协议，只用于证明混淆存在，不作为最终表）：

| 权重训练 | BN 统计量 | 干净 | 4 dB | 0 dB |
|---|---|---:|---:|---:|
| clean | clean | 99.56 | 62.29 | 41.16 |
| clean | 4 dB 噪声训练窗 | 79.98 | **98.77** | 56.94 |
| clean | 0 dB 噪声训练窗 | 24.64 | 75.80 | **96.70** |

这说明：同一组 clean-trained 权重，只要把 BN 统计量换到 4 dB 或 0 dB 的目标分布，对应噪声点的准确率可以升到 98.8/96.7，甚至高于 noise-trained + noise BN 的 97.1/87.4。至少在这个控制下，“噪声准确率由训练分布决定”不成立；更准确的说法是“BN 统计量与测试分布的匹配程度主导了表观抗噪性”。

同时，当前 Discussion 建议“clean 配置 + 检测器在噪声升高时切换 calibration”，这本身就是一个双 BN 统计量库。它与摘要里的“A model therefore cannot be both”自相矛盾。应改为：

> 单一固定 BN 配置不能在两端同时最优；保存 clean/noise 两套统计量并按输入分布切换，可以同时服务两端。

**修复：** 主表增加 2×2（权重分布 × BN 统计量）和 dual-BN 行；3–5 个种子；不要再用“training distribution decides”作为无条件结论。

### P0-3：切分、标准化与文档不一致

- `run_final.py:30-31` 实际是 test 30%，再从剩余 70% 中取 20% 作 validation，即 **56/14/30**，不是论文写的 70/10/20。
- `run_final.py:28` 在切分前对全部 1010 条做 `StandardScaler`，测试集统计量进入了训练预处理。按位置标准化时影响可能不大，但仍是 transductive leakage。
- validation 集在 `run_final.train()` 中完全没有使用，14% 数据被闲置。
- 随机窗口切分没有 recording/file 级分组。若同一段记录的重叠窗口进入训练和测试，干净准确率会虚高。过程文档自己把这一点列为“最容易被攻击的点”，但主实验没有解决。

**修复：** 先固定 outer test，再在 train 内切 validation；scaler 只在 train 上 fit；能拿到 recording ID 时按记录分组切分。拿不到时，论文必须明确写“window-level split, not a generalization estimate”，不能把 99% 说成跨记录性能。

### P0-4：统计推断不足，若干结论没有数据支持

测试集 303 条，1 条 = 0.33 个百分点。主表 0.22 点的“架构差异”小于 1 个测试窗口。3 个种子的配对差值 95% CI（t 分布，df=2）如下：

| 比较 | 差值 | 95% CI | 解释 |
|---|---:|---:|---|
| Ref − NoPad, clean Acc | +0.11 | [−0.36, +0.58] | 不能排除 0 |
| Ref − MS, clean Acc | +0.22 | [−0.25, +0.69] | 不能排除 0 |
| Ref − NoPad, clean-trained 0 dB | −3.32 | [−6.96, +0.33] | 不能排除 0 |
| Ref noise − Ref clean, 0 dB | +50.27 | [+32.39, +68.15] | 大效应，支持分布效应 |
| NoPad BN clean → clean | +26.18 | [+8.51, +43.85] | 支持 |
| NoPad BN clean → 0 dB | −33.00 | [−44.65, −21.36] | 支持 |
| NoPad − Ref, noise-trained 4 dB | +1.50 | [−2.30, +5.29] | “most robust”不成立 |

尤其注意：

- “Clean accuracy is architecture-insensitive”目前只是“差异小于噪声”，没有做等价性检验（TOST），不能写成已证明。
- “NoPad is the most robust of the three under 4 dB”在 3 个种子下 CI 跨 0，不能作为摘要级结论。
- 表值使用总体标准差，且没有说明 5 次噪声抽样与 3 个种子的层级关系。

**修复：** 5 个种子；固定 outer test 做配对比较；报告配对 bootstrap 或 t 区间；预先写死等价边界（建议 ±0.5 点）；同时报每个测试窗口的预测，便于 McNemar/配对 bootstrap。

## 四、重要但非阻断的问题（P1）

### 4.1 “五个缺陷”与“三处不一致”需要事实核查

- 主稿列的五个缺陷是：硬编码路径、`squeeze`、训练中调用 `test()`、第三方 label smoothing 导入、padding 后归一化。
- 过程文档列的五个是：`.cuda()`、`squeeze`、偶数核 `padding="same"` 警告、硬编码路径、训练中调用 `test()`。
- 代码实际是在切分前做 `StandardScaler`，不是“padding 后归一化”；BN 在 padding 后是正常结构。该条应删除或改写。
- 原论文摘要说的是“larger convolution kernel”，没有明确承诺多尺度；“single kernel”不一定构成与论文的矛盾。把“MS”说成“reference names but does not implement”目前证据不足。
- “equal output size”由 padding 实现是事实，但更像实现细节，不是论文与代码的矛盾。建议改为“equal-size claim is implemented by zero padding, with a compute consequence”，不要写成学术不端式指控。

更稳妥的表述是：**1 个实质性训练缺陷 + 4 个可复现性/移植性问题**，而不是“五个同等严重的缺陷”。

### 4.2 噪声协议描述不完整

`run_final.py:89` 每个 batch 抽一个 SNR，`add_noise` 用 batch 的 RMS 定噪声功率；测试时 `acc_noisy` 用固定的 5 个噪声种子。论文只写“SNR drawn uniformly”，没有说明是 per-batch、per-window，还是 per-sample；也没有说明 5 次 draw 的随机种子在不同模型间是共享的。应写清楚。

### 4.3 “calibration”术语冲突

这里的 BN 统计量重估是 AdaBN 式归一化适配，不是概率校准。建议全文改为“BN statistic re-estimation”或“normalization adaptation”，把 “calibration” 留给 ECE/NLL 等不确定性校准。

### 4.4 参数量与成本表述

MS 参数量是 84,746，不是 81,674。主稿第 249 行附近的“unchanged parameter count (81,674)”会把 MS 也算进去，需改成“Ref/NoPad 均为 81,674；MS 为 84,746”。

### 4.5 缺少外部基线和更完整的噪声曲线

当前只有 MIXCNN 内部变体，没有 WDCNN、DRSN 或一个简单非深度基线。若论文主张“训练分布比架构重要”，至少应加入：

- 一个已发表强基线（WDCNN 或 DRSN）；
- 一个简单频谱/线性基线（本审查已跑出 100% clean，成本极低）；
- −4/0/4/8/12 dB 的完整曲线，而不是只有 0/4 dB 两个点。

### 4.6 数据与代码可复现性

- 只有 `cwru_data.npy`/`cwru_label.npy`，没有 raw CWRU 文件、recording ID、负载/故障尺寸/采样率映射，也没有 1010 条窗口的生成脚本或校验和。
- 没有 `requirements.txt`、随机种子清单、表格生成脚本、代码仓库 URL/commit。
- `smith2015cwru` 在 bib 中存在但正文未引用；CWRU 数据来源没有正式引用。
- 我已修复 `code/` 直接运行时找不到 `../data` 的路径问题，并给 `run_seed3_extra.py` 加了断点续跑；原脚本会从空列表重新写文件，存在覆盖已有结果的风险。

### 4.7 论文形态

当前是 3 页 IEEE conference 模板，没有架构图、没有噪声曲线、没有 per-class 结果。以现有证据，适合先投 4 页左右的会议/可复现性短文；期刊版需要扩充实验、基线和数据分析。B 线代码仍是 smoke test（例如 `train.py` 中 `enable_qat` 未导入），不应混入主论文。

## 五、建议的论文重构

### 5.1 新标题方向

避免“Architecture or Training Distribution?”这种二元对立，因为它遗漏了 BN 统计量和切分协议。可选：

- *Saturation, Split, and Normalization: What a 99% Bearing-Fault CNN Actually Measures*
- *The Normalization Dial: Re-evaluating Noise Robustness of a Bearing-Fault CNN*
- *When Clean Accuracy Cannot Rank Architectures: A Controlled Bearing-Fault Study*

### 5.2 新贡献顺序

1. **可复现性审计**：原脚本的 inference-mode 缺陷；99.34% 复现；输出长度由 padding 实现；参数量和 FLOPs。
2. **饱和性证据**：同一切分下，128-bin log-FFT + 逻辑回归达到 100%；0.22 点架构差异小于 1 个测试窗口。
3. **2×2 归一化实验**：clean/noise 权重 × clean/noise BN 统计量；dual-BN 行；说明“单一 BN 配置的权衡”和“双库切换的可行性”。
4. **成本 Pareto**：NoPad 的 FLOPs 降到约 1/3.95、墙钟降到约 1/7，clean 差异在等价边界内。

关键结果：

| 结果 | 数值 |
|---|---|
| 128-bin log-FFT + logistic，clean | 100% |
| 六个 CNN 变体 clean | 97.0–98.5% |
| NoPad − Ref，clean | +0.10 点，95% CI [−0.70, +0.90] |
| Ref 0 dB，clean → noise-trained | 43.47 → 97.38（+53.91） |
| NoPad 0 dB，clean → noise-trained | 59.65 → 97.70（+38.05） |

| NoPad clean-trained 0 dB vs Ref | +16.18，CI [+9.63, +22.73] |
| NoPad 前向 FLOPs vs Ref | 38.8M vs 153.0M |
| 纯多尺度 vs Ref，clean / 0 dB | −0.39 / −1.63，CI 均跨 0 |

结论发生了变化：旧的 batch-level 噪声协议给出的“NoPad 干净 72.7 / 0 dB 87.4”没有在逐窗口协议下复现；v2 为 97.2/97.7。因此旧稿的“训练分布造成大权衡”和“多尺度 18 点惩罚”都不能保留。BN 仍然是真实因素，但应表述为“单一固定 BN 库不能同时最优，双库可切换”，而不是“模型不能两者兼得”。
